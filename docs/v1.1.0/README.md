# v1.1.0：节点和中转支持 UDP

## 1. 为什么做

MSBOOST 启动器 v1.2.0 起可以选用 TCP 还是 UDP 连接节点，网站 v2.11.0 起节点和中转同时提供 UDP。整体方案和网站、启动器的真机测试见启动器仓库的 `docs/MSBOOST-UDP传输整改计划.md`。本版让本地版跟上：同步网站 v2.11.0 的执行引擎和安装脚本，朋友中转也支持 UDP。

## 2. 改了什么

| 项目 | 内容 |
|---|---|
| 同步网站 v2.11.0（PR #6） | 部署和升级给安装脚本传 `MSBOOST_UDP=1`，节点在同一端口开 UDP；部署、升级、取回配置的结果带公网 UDP。Windows 上跑不了 mihomo，带 UDP 的配置显示「已开启」，提示用启动器检查。自备中转和前置机随配置中转 UDP。GOST 固定值改从网站的 `deploy/install-agent.sh` 提取 |
| 朋友中转 UDP（PR #7） | 分享文字末尾的「· 支持 UDP」标记；中转服务器先检查目标的 UDP 端口，没有回应才中转 UDP；节点一方的新配置加上 UDP 绑定；中转列表和「复制入口」带 UDP。做法见规划 §4.7 |
| 发版前 | 结果页 UDP 一行写明启动器要 v1.2.0，以及服务器防火墙已自动放行、安全组要自己放行；升级开启 UDP 的提示改为本地版的说法：新配置已直接替换启动器里的配置，不用重新导入 |

## 3. 兼容

- **启动器**：v1.1.2 及更早的启动器会把 TCP 和 UDP 混着用。本版部署、升级、取回的配置会直接替换启动器里这台服务器的配置，所以要先把启动器升级到 v1.2.0。发布说明开头写明了这一点。
- **朋友中转**：双方有一方用 v1.0.0 时只走 TCP，照常能用。
- **只开了 TCP 的旧节点**：不升级照常能用；在本地版里升级后开启 UDP。
- **本地数据**：`local` 文件夹的格式不变，覆盖升级即可。

## 4. 实测记录

- 网站 v2.11.0 的安装脚本和引擎：节点 UDP、自备中转、两跳加前置机，见整改计划 10.4 和 11.8。
- 朋友中转 UDP（2026-11-01，Debian 13）：
  - 检查脚本：安静的端口判为可以中转 UDP；只回应 SSDP、只回应 memcached 的端口和关闭的端口都判为只走 TCP。
  - 用本地版的代码给一台开了 UDP 的测试节点建朋友中转：真实的 mieru 端口对探测没有回应，中转按 TCP 和 UDP 建好；另一台机器用 mihomo 经这条中转分别走 TCP 和 UDP，出口都是节点本身，下载 2 MB 分别用了 3.4 秒和 4.5 秒；中转列表显示支持 UDP；删除后没有残留。
- 本地版界面：等第 5 节的实测。

## 5. 实测步骤

### 准备

- 在仓库的 Actions 页面打开 `release-v1.1.0` 分支最新一次通过的 `ci` 运行，下载 `MSBOOST-Local-dev-xxxxxxx-win-x64`，解压到 MSBOOST 启动器 v1.2.0 所在的文件夹。
- 需要两台 Debian 服务器：一台部署节点，另一台建中转。

### 测试 1：部署

1. 部署一台新节点。结果里 UDP 一行显示「已开启」，并写明启动器要 v1.2.0 或更新版本。
2. 在启动器里选中这份配置：「加速」页出现 TCP / UDP 切换；选 UDP 做「网络检测」，结果正常。

### 测试 2（可选）：升级旧节点

有 v1.0.0 部署的节点时，在本地版里升级它。提示「节点已升级并开启了 UDP」；启动器里这份配置出现 TCP / UDP 切换。

### 测试 3：自备中转

用测试 1 的配置在另一台服务器上建自备中转。提示「TCP 和 UDP 都能用」；在启动器里选中新配置，选 UDP 能加速。

### 测试 4：朋友中转

1. 「我用朋友的中转」选测试 1 的配置，复制的文字末尾有「· 支持 UDP」。
2. 「我帮朋友中转」粘贴这段文字：目标后面显示「· 支持 UDP」；建好后结果写「TCP 和 UDP 都能用」，发回的文字末尾也有「· 支持 UDP」。
3. 回到「我用朋友的中转」粘贴发回的文字：显示「✓ 也中转 UDP」；生成的新配置在启动器里能选 UDP。

### 测试 5：中转列表

「中转」页读取中转服务器的列表：测试 4 的那一行显示「支持 UDP」；「复制入口」复制的文字末尾有「· 支持 UDP」。

### 回报

把每项测试的结果发过来，有问题时附上截图。测试完可以在「中转」页删除测试中转，再卸载测试节点。

这个分支合并后，等你说发布再打标签：

1. 我在 main 上打标签 `v1.1.0` 并推送，CI 生成草稿 Release（三个文件）。

   - Windows 安全中心扫描 zip 和解压后的 exe，没有报毒；

4. 在网站「系统设置 → MSBOOST 本地版」填写版本 `v1.1.0`、下载地址和 zip 的 SHA-256（在 `SHA256SUMS.txt` 里）。
5. 在 GitHub 上发布草稿 Release。
