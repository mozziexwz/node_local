# MSBOOST 本地版 开发规划

> 2026-10-21 定稿。实现中与最初规划不同的地方已直接改在本文，见文末「变更记录」。

## 1. 背景

- 网站（MSBOOST.DE / mozziexwz/node）的「免费部署工具」要求会员在网页填写自己 VPS 的 SSH（密码或私钥），由执行机代为登录部署。网站承诺 SSH 只用于当次任务、不落库，但仍有用户不愿把 SSH 交给任何网站。
- 本地版是一个 Windows 桌面程序：在用户自己的电脑上直接 SSH 到用户的 VPS，完成网站上只涉及用户自己服务器的功能。SSH 从头到尾不离开本机，也不经过网站。
- 做法：把网站执行机的引擎（同一套脚本、同一套受管目录）搬进桌面程序，界面沿用 MSBOOST 启动器的外壳。部署出来的节点和网站部署的完全一样，配置文件直接给启动器用。

## 2. 已确认的决定

| 事项 | 决定 |
|---|---|
| 形态 | 独立程序 `MSBOOST-Local.exe`，在本仓库单独发布；不需要管理员。和启动器解压到同一文件夹时，部署出的配置直接进启动器的 `configs\` |
| 首版功能 | 部署/升级节点、自备中转 + 中转管理、卸载清理。DD 放到后续版本，首版不内置 reinstall 脚本 |
| SSH 密码 | 不保存。只记服务器 IP、端口、登录方式、私钥文件位置和已确认的指纹；密码和私钥口令只在内存里 |
| 许可证 | GPL-3.0，与启动器一致 |
| 文案 | 界面只说 MSBOOST，不出现 mieru/mihomo/GOST（只在「开源许可」里列出） |

## 3. 首版功能

| 功能 | 网站有没有 | 说明 |
|---|---|---|
| 服务器身份核对 | 有 | 首次信任并钉扎指纹（存本机），变化时拒绝，用户核实后显式替换；保留严格模式（对照服务商控制台） |
| 部署节点（全新） | 有 | 同一个 msboost.sh，`MSBOOST_FORCE_FRESH=1`，生成新凭据和端口 |
| 升级/修复节点（保留配置） | 没有 | root 不带参数跑新版脚本，凭据、端口、低熵档位不变（网站 `规划/节点整改` §3）；`MSBOOST_SERVER_IP` 取原配置里的入口 IP；没部署过的服务器拒绝 |
| 取回配置 | 没有 | 新开 SSH 读 `/root/直连.json` 并按部署的标准校验；解决部署中途断线拿不到配置 |
| 节点状态 | 没有 | 两个服务是否运行、引擎版本、BBR 状态 |
| 自备中转（可加前置机） | 有 | GOST 固定 URL+sha256，带宽 1–10 Mbps（默认 5），与网站一致 |
| 中转服务器管理 | 有 | 列表、暂停、恢复、重启、限速、删除 |
| 卸载清理 | 有 | 先预览（带摘要）再确认，范围 `msboost` 或 `relay` |
| 安装过程实时日志 | 没有 | 网站只给阶段；本地是用户自己的服务器，可以显示安装输出（节点密码打码，不显示配置正文） |

不做：DD（后续版本）、中转目标校验（用启动器「网络检测」做端到端验证）、中转码、我使用的中转、捐赠权益线路、枫叶/兑换、工单、文章——这些需要网站账户、数据库或站方服务器。

## 4. 技术方案

### 4.1 总体

Go 1.27.1 + Wails v2.16.0 + React 19，与启动器同一套工具链；Windows x64 便携 zip；manifest 用 `asInvoker`。

### 4.2 引擎：从网站同步

- 网站的执行机代码在 `internal/` 下，别的模块不能 import；网站模块路径 `github.com/mozziexwz/node` 配 v2.x 标签也不符合 Go 的版本规则。所以复制。
- `go run ./scripts/syncnode -tag <网站标签> [-source ..\MSBOOST.DE]` 从网站仓库的固定标签取文件（`git cat-file`，字节不变）：
  - `internal/executor` 的源码和测试，不含 `client.go`（轮询网站）、`sftp_ownership.go`（网站备份用）和 `unattended_test.go`（DD 测试，需要 reinstall 脚本）。依赖只剩 x/crypto/ssh。
  - `installers/node/msboost.sh`，与网站同一路径，引擎测试按这个相对路径读取它。
  - `installers/gost.json`：从网站 `deploy/agent-executor.env.example` 提取的 GOST 下载地址和 sha256。
  - 来源标签、提交号和每个文件的 sha256 写进根目录 `UPSTREAM.json`。
- 同步来的文件不手改。本地新增放在 `internal/executor/local_*.go`，同步时不碰；它们和引擎同包，可以直接用 `marker`、`failRemote`、`ParseClientConfig` 等现成函数。
- `installers` 包用 `go:embed` 内嵌安装脚本和 GOST 固定值，`installers.NewEngine()` 返回配好 GOST 的引擎，`installers.NodeScript()` 返回部署要用的脚本和 sha256。
- `.gitattributes` 让 `installers/node/` 保持原始字节：Windows 检出成 CRLF 会让远端 bash 出错，sha256 也会变。
- 校验：`installers` 包的测试按 `UPSTREAM.json` 核对 sha256；CI 再用 `syncnode -check` 从网站仓库重新生成，逐字节比对。

### 4.3 应用层

- `internal/servers`：服务器列表，存 `local\servers.json`，原子写。不含任何密码。
- `internal/tasks`：
  - 把界面请求拼成 `executor.Job`，带可取消的 context 运行；同一台服务器同时只跑一个任务。
  - 任务记录（不含秘密）存 `local\tasks.json`，自备中转的备注也记在这里。
  - 取消只断开连接，服务器上的安装可能还在跑；界面要说明，并提示稍后用「节点状态」或「取回配置」确认。
- 配置文件存到 exe 旁的 `configs\`，文件名默认用服务器备注（没有就用 IP），清理规则照网站 `configName`；重名先问。启动器在同一目录时立即可用；否则提供「导入到启动器…」（选一次启动器目录并记住）和「另存为…」。
- 本地版自己的数据都放 `local\`（WebView2 缓存、日志），不和启动器的 `data\`、`logs\`、`settings.json` 冲突。
- 设置里可选「SSH 经本机 SOCKS5 代理」，应对国内直连 VPS 不稳定；部署后的端口可达检查仍然直连。

### 4.4 界面

- 沿用启动器外壳：顶部标签、底部状态栏、`style.css` 配色字体、`components.tsx`。窗口比启动器大，尺寸在 M1 出样稿定。
- 标签：服务器 / 部署节点 / 中转 / 卸载清理 / 任务记录 / 设置与关于。
- 进度：阶段（连接、预检、安装、自测、取配置）加可展开的实时日志；失败时显示阶段和中文原因。引擎的诊断文案是给网站写的（提到「执行机」「管理员」），界面层按诊断编号换成本地说法。
- 不要托盘：关闭窗口即退出；有任务在跑时先确认。

### 4.5 安全

- 密码和私钥口令只在内存里，任务结束即清；日志打码 SSH 密码、口令和节点密码。
- 程序只连接用户自己的服务器，不上报、不统计、不连网站。仓库公开，可以自己审计。
- 防误报（沿用启动器经验）：不碰注册表代理项、不结束其他进程、不调用 Windows 凭据加密接口；发版前做可疑字符串对比，并用 Chrome 实际下载测试。

### 4.6 与网站、启动器的关系

- 远端目录和服务名与网站完全一致：用本地版装的节点或中转，网站的卸载清理和中转服务器管理照样能处理，反过来也一样。
- 本地版建中转不写使用者记录（`meta.json`）：网站的校验只接受带网站账户邮箱的记录，而本地版没有账户。中转照常受管，网站和本地版都能列出、管理和清理。
- 网站侧要做的事交给 node 会话（写 `规划/` 交接说明）：下载页加本地版入口和源码链接（GPL §6）；使用指南第 2 步加一句「不想在网站填 SSH？用 MSBOOST 本地版」。

## 6. 验证

- CI：Linux 跑全部测试（同步来的引擎测试要调用 bash 和 python3）并做同步校验；Windows 跑 vet、测试并构建。
- 实机（临时 Debian 12 VPS）：
  1. 部署 → 配置放进启动器 → 启动器「网络检测」三项正常 → 进游戏。
  2. 升级（保留配置）→ 原配置照常连接；对没部署过的服务器拒绝。
  3. 部署中途断开网络 → 「取回配置」拿到可用配置。
  4. 第二台 VPS 做中转（再加前置机）→ 启动器经中转进游戏；中转管理里暂停/恢复/限速/删除。
  5. 卸载清理的预览与执行；网站的清理工具能识别本地版装的组件。
  6. 主机密钥变化时拒绝连接；SOCKS5 代理模式能部署。
- 干净 Win10 虚拟机：普通用户账户运行；Chrome 下载 zip 不被拦截；`local\` 里找不到任何密码。

## 7. 后续版本可考虑

- DD 重装 Debian 12（内置固定提交的 reinstall 脚本和 manifest 校验）。
- 「帮朋友建中转」：建中转只需要朋友节点的 IP 和端口，朋友在自己的本地版里把配置入口改成中转地址。双方都不用交出 SSH 或节点密码，可以替代网站中转码的部分场景。
- 支持 sudo 的非 root 用户（引擎目前只接受 root）。

## 变更记录

- 2026-10-21（M0）：同步脚本由 PowerShell 改为 Go（`scripts/syncnode`），以便按字节复制、CI 也能跑；`UPSTREAM.json` 放在仓库根目录；内嵌脚本放 `installers/`（与网站同路径，引擎测试按此路径读取）；本地版建中转不写 `meta.json`（原计划写 `source:"local"`，但网站的校验只接受带邮箱的记录）。
