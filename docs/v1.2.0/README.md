# v1.2.0：部署节点时自动配置 fail2ban

## 1. 为什么做

服务器的 SSH 一直暴露在公网上被扫。网站 v2.12.0 起，部署和升级节点时会像开启 BBR、同步系统时间和安装依赖一样，自动配置 fail2ban 保护 SSH，默认参数沿用 `fail2ban.sh` 一键脚本。本版让本地版跟上：同步网站 v2.12.0 的执行引擎，部署和升级都带上这一步。

网站的白名单是全部执行机。本地版没有执行机，由这台电脑直接连服务器，所以白名单只放这台电脑所在的 /16：家用宽带换了 IP 一般也还在这个网段里。

## 2. 改了什么

| 项目 | 内容 |
|---|---|
| 同步网站 v2.12.0（PR #10） | 执行引擎带上 `fail2ban.go`：请求带 `Fail2ban` 时，部署和升级在节点装好以后配置 fail2ban，结果带 `health.fail2ban`。节点安装脚本没有变 |
| 部署和升级（PR #10） | 两种任务都带 `Fail2ban{ClientBits: 16}`，白名单只有服务器看到的本机来源地址所在的 /16（开了 SSH 代理时是代理的出口）。升级前先检查这个参数。部署发出的脚本仍和网站引擎逐字节一致，测试对带与不带 SSH 防护两种情况都做了比对 |
| 界面（PR #10） | 进度在「本机自测」和「保存配置文件」之间多了「配置 SSH 防护」，步骤列表改成 6 + 5 两列；结果在 BBR 后面多一行「SSH 防护」：已开启（附封禁规则）、服务器已有 fail2ban 配置没有改动、没有开启（不影响节点使用）、没有配好（请检查 fail2ban 服务）；部署前的提示和「升级节点」的说明提到它 |
| 发版前 | 发布说明、本说明、README 和规划 |

## 3. 兼容

- **服务器上已有 fail2ban 配置**：有任何 `*.local`、别的 `jail.d/*.conf`，或改过包里的配置文件时，不安装也不改动，结果显示「服务器已有 fail2ban 配置，没有改动」。有的服务商镜像自带 fail2ban 和一个 `jail.d/bantime.conf`，也按已有配置处理。
- **卸载节点**：不卸载 fail2ban，也不删它的两个配置文件，和 BBR 设置一样。
- **启动器**：没有变化，仍要 v1.2.0 或更新版本。
- **本地数据**：`local` 文件夹的格式不变，覆盖升级即可。

## 4. 实测记录

- **网站 v2.12.0 的 fail2ban 步骤**（2026-11-12，Debian 12 和 13）：全新部署、老节点升级、封禁与解封、执行机白名单、IPv6 地址、已有配置（`fail2ban.sh` 的配置和服务商镜像自带的配置）、重复升级不重启、白名单变化后重启，都符合预期。Debian 13 的 OpenSSH 把登录日志的进程名改成了 `sshd-session`，Debian 自带的日志匹配按 `ssh.service` 收，照样能封。
- **本地版**（2026-11-12，三台：Debian 12 一台、Debian 13 两台）。用本地版的任务层操作，也就是去掉窗口的程序本身，用私钥登录：
  - 先删掉 fail2ban 再升级节点：从零装好，白名单只有本机的 /16。升级前从本机输错的 6 次被忽略；另一台机器输错到第 5 次被封，只封 SSH 端口，节点端口照常能连；解封后恢复。
  - Debian 12 上再次升级：fail2ban 的配置没变，没有重启，节点配置也没变。
  - 镜像自带 fail2ban 的服务器全新部署：显示已有配置，原文件和服务都没动。
  - 三台的进度里都实时出现「配置 SSH 防护」。
- **界面**：用指南截图工具的模拟数据渲染了进度页、结果页和服务器详情。真实程序的界面还没测，见第 5 节。

## 5. 实测步骤

### 准备

- 在仓库的 Actions 页面打开 `release-v1.2.0` 分支最新一次通过的 `ci` 运行，下载 `MSBOOST-Local-dev-xxxxxxx-win-x64`，解压到 MSBOOST 启动器所在的文件夹。
- 需要一台 Debian 服务器部署节点；有没装过 fail2ban 的旧节点更好。

### 测试 1：部署

部署一台新节点。进度里在「本机自测」之后出现「配置 SSH 防护」；结果里「SSH 防护」显示「已开启」，后面写着封禁规则。

### 测试 2（可选）：升级旧节点

在本地版里升级一台没有 fail2ban 的旧节点：结果里「SSH 防护」显示「已开启」，原配置照常能用。

### 测试 3（可选）：已有配置

服务器上已经有自己的 fail2ban 配置时，部署或升级的结果显示「服务器已有 fail2ban 配置，没有改动」。
